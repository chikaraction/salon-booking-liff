# ADR-008: E2Eテスト(Playwright)と手元のSupabase

- ステータス: 承認済み
- 日付: 2026-10-27

## Context(状況)

ユニットテスト(Vitest)は `src/lib/` の純粋ロジックしか対象にしていない。画面の崩れ・予約の流れ・
ダブルブッキングの競合・アクセス制御は、マージ前に verify-booking スキルのチェックリストで
手作業で確かめている。特にスマホ幅の崩れは機種ごとに幅が違い、手作業では確認しきれない。

E2Eテストは予約を作ったりキャンセルしたりするのでDBに書き込む。いまのSupabaseは開発と本番を
兼ねた1つのプロジェクトで、本番に切り替えると客の実データが入る。開発機にはDockerがなく、
これまでマイグレーションの検証はPGliteで代用してきた。

## Decision(決定)

- **E2EテストはPlaywright(`@playwright/test`)で書く。** テストは `e2e/` に置き、
  `npm run test:e2e` で実行する
- **テスト用のDBは手元のSupabase(`npx supabase start`)にする。** 開発機にWSL2とDocker Desktopを入れる
  - テストを始める前に `npx supabase db reset` でマイグレーションと `supabase/seed.sql` を
    当て直し、毎回同じデータから始める
  - アプリはスタブモード(`NEXT_PUBLIC_LIFF_STUB=1`)で起動し、接続先を手元のSupabaseに向ける。
    接続先は Playwright の起動設定から環境変数で渡し、`.env.local`(リモートのDB)は使わない
  - 管理画面のテスト用アカウント(オーナー・スタッフ)は手元のSupabaseにだけ作る
- **CIには入れない。** マージの前に手元で `npm run test:e2e` を実行する運用にする
- **範囲**
  1. 画面幅のチェック: 客側・管理画面の全画面を、幅 320 / 360 / 375 / 393 / 430 / 440px、
     タブレット、PCで開き、横スクロールとカードからのはみ出しを自動で判定してスクリーンショットを残す
  2. 予約の流れ: 客の予約・変更・キャンセル、ダブルブッキングの防止(2つのブラウザで同じ枠を
     同時に確定)、管理画面のアクセス制御(未ログイン・スタッフロール)
  3. 設定の反映: 管理画面で変えた設定(営業時間・締切・メニュー)が客側の予約画面に出ること
- **ブラウザ**: Chromium・WebKit・Firefox。発注者の確認環境がスマホは iPhone(Safari)、
  PCは Firefox なので、Chromium だけにしない
- **範囲外(verify-booking に残す)**: LINEアプリ内での動作・同意画面・リッチメニュー、
  LINEへの返信とリマインドの到着、Cloudflare 固有の動き(Cron・Secret・CPU時間)、
  iPhone 実機でだけ起きる崩れ
- E2Eで確かめられるようになった項目は、verify-booking のチェックリストにその旨を書く

## 理由

- 手元のSupabaseなら本番のデータを壊す心配がなく、`supabase db reset` で数秒で作り直せる。
  何度でも同じ状態からテストを始められる
- マイグレーションを本物のPostgres+Supabase(認証・RLSを含む)で確かめられるようになる。
  PGliteでは認証の部分を手書きのスタブで済ませていた
- 開発機のメモリは31GBあり、Supabase一式を動かしても余裕がある
- Playwright は1つのテストを複数のブラウザと画面幅で回せ、2つのブラウザを同時に動かす
  競合のテストも書ける

## 検討した代替案

- **E2E専用のSupabaseプロジェクトをクラウドに作る**: 導入は画面で作るだけで楽だが、テストの
  たびの作り直しにSQLやスクリプトが要り、1週間使わないと一時停止する。→ 却下
- **今のプロジェクトでテストする**: 本番に切り替えたあとは客のデータと混ざる。→ 却下
- **CIで回す**: 前に検討して見送った。→ 今回も入れない

## Consequences(影響)

- 良い点: verify-booking の手作業が減る。スマホ幅の崩れを幅ごとに機械で確かめられる。
  マイグレーションを本物の環境で確かめられる
- 注意点: Windows の WebKit は iPhone の Safari と同じではない。iOS の日付・時刻入力の
  崩れのようなものは再現しない可能性が高く、iPhone 実機での確認は残る
- 開発機にWSL2とDocker Desktopが必要になる(OSへのインストールなので開発者の作業)
- テストを回す前に `npx supabase start` で手元のSupabaseを起動しておく必要がある
