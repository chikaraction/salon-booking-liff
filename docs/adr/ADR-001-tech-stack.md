# ADR-001: 技術スタックとホスティング

- ステータス: 承認済み
- 日付: 2026-07-14

## Context(状況)

実運用する商用システムだが、運用コストは無料〜月数百円に抑える必要がある。開発はAI主導で行うため、
AIが扱いやすい(学習データ・ドキュメントが豊富な)技術を選ぶことが品質に直結する。
規模は小さく(数百ユーザー、予約は月数百件程度)、高いスケーラビリティは不要。

重要な制約: Vercelの無料プラン(Hobby)は**商用利用が規約で禁止**されている。
実店舗の予約システムは商用利用にあたるため、無料で商用利用可能なホスティングを選ぶ必要がある。

## Decision(決定)

- **フロントエンド+API**: Next.js(App Router)
- **ホスティング**: Cloudflare Pages / Workers(無料枠・商用利用可)
- **データベース+認証**: Supabase 無料枠(PostgreSQL / Supabase Auth)
- **定期処理(リマインド送信)**: Cloudflare Workers の Cron Triggers(無料)

## 理由

- Next.js + Supabase はAI開発との相性が最も良い組み合わせの一つ。コード例が豊富で、AIに指示するだけで品質の高い実装が得られやすい。
- Cloudflareの無料枠は商用利用が許可されており、コスト制約(無料〜数百円)を満たす。
- SupabaseはPostgreSQLなので、ダブルブッキング防止に必要なDB制約(ADR-004)が使える。
- 認証・DB・ストレージが一体で、AI主導開発でのインフラ構成の複雑さを最小化できる。

## 検討した代替案

- **Vercel Hobby**: 開発体験は最良だが商用利用不可。有料プラン($20/月〜)は予算超過。→ 却下
- **VPS(さくら等、月数百円)**: 商用可で安価だが、サーバー管理(セキュリティ更新等)の運用負担がAI主導・指示中心の体制に合わない。→ 却下
- **Google Apps Script + スプレッドシート**: 無料だが、同時予約の排他制御が脆弱で実運用の予約システムには不向き。→ 却下

## Consequences(影響)

- 良い点: 月額ほぼ0円で運用可能。DB制約による堅牢な予約管理ができる。
- 注意点: Next.jsをCloudflareで動かすにはアダプタ(OpenNext等)が必要で、Vercelよりひと手間かかる。Supabase無料枠は1週間アクセスがないとDBが一時停止するため、定期pingか有償化($25/月)の判断が将来必要になる可能性がある(小規模店舗なら日常アクセスで通常は問題ない)。
