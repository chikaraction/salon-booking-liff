# ADR-002: 予約チャネルと通知(LINE中心)【改訂v2】

- ステータス: 承認済み
- 日付: 2026-07-15(v1: メール基本案を置き換え)

## 改訂の経緯

v1では「LINE無料枠200通/月では足りない」と判断しメール通知を採用したが、以下の追加情報により前提が変わった:

- 全顧客(約200人)と既にLINE公式アカウントでやり取りしており、友だち登録済み
- 予約は月100件未満の見込み
- LINE非利用客は電話等で予約し、オーナーが管理画面で代行登録するため、システムで直接対応する必要がない
- LINEの課金仕様: 客の操作に対する**応答メッセージは無料・無制限**。無料枠200通/月を消費するのは**プッシュ送信のみ**

## Decision(決定)

- 予約の入口は**既存のLINE公式アカウント**。リッチメニューから予約画面(LIFFアプリ)を開く
- 通知の設計(プッシュ消費を最小化):
  - **予約確認**: 予約完了画面に表示+LINEトークに送信(無料の応答枠を優先利用)
  - **前日リマインド**: プッシュ送信 = **1予約につき1通のみ消費**
  - **キャンセル確認**: 客自身の操作時は画面表示で完結(プッシュ不使用)
- 月100予約でもプッシュは約100通で、無料枠200通の半分に収まる

## 超過リスクの管理

- 月のプッシュ送信数が150通を超えたら管理画面に警告を出す
- 恒常的に超えるほど繁盛した場合は、ライトプラン(月5,000円)への移行か、リマインドの一部メール化を新ADRで再検討する

## 検討した代替案

- **メール通知(v1案)**: 全客層カバーが利点だったが、電話予約客はオーナー代行で吸収されるため利点が消滅。既存のLINE運用と分断され、客に新しい行動(メール確認)を強いる。→ 却下
- **SMS**: 1通約10円のコストと、既存LINE運用との重複。→ 却下

## Consequences(影響)

- 良い点: 客は今まで通りLINEだけで完結。オーナーの運用も現在の延長線上。追加コスト0円。
- 注意点: LINE公式アカウントのMessaging API設定(チャネル作成、LIFF登録)が初期構築で必要。リマインドの送信数を管理画面で可視化しておくこと。
