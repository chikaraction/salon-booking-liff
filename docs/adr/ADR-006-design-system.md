# ADR-006: UIデザインシステム

- ステータス: 承認済み
- 日付: 2026-07-15

## Context(状況)

客側(LIFF・スマホ)と店側(管理画面・PC/タブレット)の2つのUIを作る。開発はAI主導のため、**AIが正確に生成できる(学習データが豊富な)UI技術**を選ぶことが品質を直接左右する。客層は40代以上中心で、読みやすさ・押しやすさが最優先。デザイナーはいないため、デフォルトのままでも整って見える仕組みが必要。

## Decision(決定)

- **Tailwind CSS + shadcn/ui** を客側・店側で共通採用する
- カスタマイズ方針:
  - ベース文字サイズは16px以上、客側の主要ボタンは高さ48px以上(タップしやすさ)
  - テーマカラーは1色+ニュートラル(美容室らしい落ち着き。具体色はモック確認時にオーナーと決定)
  - フォントは **Noto Sans JP**(無難で高可読)。LINEらしさを出したければ **LINE Seed JP**(LINE公式の無料フォント、商用可)に差し替え可
- 店側の**予約カレンダーは自作**する(縦=時間、横=スタッフ2列のCSSグリッド)
- デザイントークン(色・余白・角丸)は1ファイルにまとめ、客側・店側で共有する

## 理由

- shadcn/uiはコンポーネントをプロジェクト内にコピーして使う方式のため、AIがコードを直接読んで修正でき、「指示→修正」のループが最も速い。現在のAI開発で事実上の標準で、生成品質が安定している
- Tailwindはスタイルがコンポーネント内で完結するため、AIの変更が他画面に波及しにくい
- ボタン・フォーム・ダイアログ・カレンダー(日付選択)など、必要な部品がほぼ揃っている
- カレンダー自作の理由: 定番のFullCalendarは「スタッフ別の列表示(リソースビュー)」が**有料ライセンス**で予算に合わない。スタッフ2名固定なら2列グリッドの自作のほうが簡単で軽い

## 検討した代替案

- **MUI(Material UI)**: 部品は豊富だがGoogle風の見た目が強く、美容室のトーンに合わせるカスタマイズが重い。→ 却下
- **daisyUI**: 手軽だが細かい調整の自由度でshadcn/uiに劣る。→ 却下
- **フレームワークなし(素のCSS)**: AI生成だと画面ごとに見た目がばらつくリスクが高い。→ 却下
- **FullCalendar(店側カレンダー)**: リソースビューが有料。→ 却下

## Consequences(影響)

- 良い点: 追加コスト0円。Claude DesignのモックからClaude Codeの実装まで同じ語彙(Tailwindクラス)で指示でき、モックと実物の乖離が小さい
- 注意点: 自作カレンダーは「予約ブロックの重なり表示」「営業時間外のグレーアウト」などを自前で実装する必要がある(ただしスタッフ2名・1日単位なら複雑度は低い)。将来スタッフが大幅に増えたら市販カレンダー再検討
