# UI仕上げ: M4bで見つけた見た目の差分と代行登録の並び順(2026-10-19)

M4bの実機確認で見つかったが、M4bのブランチでは直さないと決めた5項目を扱う。
ボタン・カレンダーの見た目は `docs/mockups/美容室LINE予約システムモック.html` で
実測して裏取りした。

## ブランチ

- `feature/ui-polish` … ②〜⑤(見た目)。項目ごとにコミットを分ける
- `feature/admin-menu-order` … ①(取得・並び順のロジック)。見た目とは混ぜない

## ① 代行登録のメニュー表示順

`fetchActiveMenus`(`src/server/admin-data.ts`)は `display_order` だけで並べている。
この値はカテゴリごとに0から振られるため、結果がカテゴリをまたいだ持ち回りになり、
同じ値どうしの順序も決まらない。詳しくは `docs/milestone-4b-plan.md` 末尾の申し送りを参照。
なお、そこで `buildMenuGroups` と書いている関数は実在せず、正しくは
`groupMenusByCategory`(`src/lib/booking.ts`)。

- 並べ替えは純粋関数にして lib に置き、(カテゴリ順, メニュー順, id)の3段で並べる。
  取得側では `category_id` とカテゴリの `display_order` も取る
- 影響する画面: 予約カレンダーの予約ダイアログ、`/admin/reservations/new`、`/admin/reservations/[id]/edit`
- 店側でもカテゴリの見出しで区切るかは、モックDを確認して決める

## ② キャンセルボタンを破壊的アウトラインにする

モックは枠 `#e6c3bd`・文字 `#c0503f`・枠の太さ1.5px。対象は店側の予約詳細の
「店側でキャンセル」と、客側 `/my` の予約カードの「キャンセル」。現状はどちらも、
ニュートラルな枠に `text-destructive` を重ねている。

- 色は `--color-primary-strong` と同じく、`--destructive` から作る派生トークンにする
- 共有の `Button` には新しいvariantを**追加**するだけにし、既存のvariantは変えない。
  白地で4.5:1以上あることを実測する

## ③ 「マイ予約を見る」をテーマ色アウトラインにする

モックは枠がテーマ色、文字がテーマ色の濃い側。現状はニュートラルな枠に
`text-primary`(白地で4.38:1でAAに届かない)を重ねている。M4bの設定フォーム3つに
重複しているクラス文字列(border-primary / text-primary-strong)を `Button` のvariantに
まとめ、「マイ予約を見る」もそれを使う。

## ④ ボタンの太さ(と枠の太さ)

モックの `<button>` 28個はすべて `font-weight: 700` で、アウトラインの枠はすべて1.5px。
実装のベースは `font-medium` で、枠は1px。`<Button>` 44箇所のうち23箇所は、個別に
`font-bold` を付けている。共有のベースを変えるか、足りないボタンにだけ足すかは未決定。

## ⑤ 予約カレンダーの時刻ラベル

- 週表示で「20:00」の左端が欠けていた。時刻の列の幅が、週表示は `w-12`、日表示は `w-14` だった
- 時刻ラベルの置き方が3通りに分かれていた。先頭は罫線の下、途中は罫線の中央、末尾は罫線の上
- モックは、時刻の列が62px幅で、どのラベルも上端を罫線にそろえて罫線の直下に置く

決定(2026-10-19、ユーザー): モックどおり、すべてのラベルを罫線の直下にそろえ、
末尾のラベルは出さない。

- 罫線はすべての目盛りに引く。ラベルは、閉店まで15分以上ある目盛りにだけ出す。
  15分は、1時間≒4remの見積もりで text-xs の1行(1rem)にあたる
- 判断は `src/lib/admin-calendar.ts` の純粋関数で行い、`TimeGutter` はラベルを並べるだけにする
- 時刻の列の幅は、日表示・スマホ・週表示のどれも `w-16` にそろえる。数字は `tabular-nums` にする
