# UI仕上げ: M4bで見つけた見た目の差分と代行登録の並び順(2026-10-19)

M4bの実機確認で見つかったが、M4bのブランチでは直さないと決めた5項目を扱う。
ボタン・カレンダーの見た目は `docs/mockups/美容室LINE予約システムモック.html` で
実測して裏取りした。

## ブランチ

- `feature/ui-polish` … ②〜⑤(見た目)。項目ごとにコミットを分ける
- `feature/admin-menu-order` … ①(取得・並び順のロジック)。見た目とは混ぜない

## ① 代行登録のメニュー表示順

`fetchActiveMenus`(`src/server/admin-data.ts`)は `display_order` だけで並べている。
この値はカテゴリごとに0から振られるため、結果がカテゴリをまたいだ持ち回りになり、
同じ値どうしの順序も決まらない。詳しくは `docs/milestone-4b-plan.md` 末尾の申し送りを参照。
なお、そこで `buildMenuGroups` と書いている関数は実在せず、正しくは
`groupMenusByCategory`(`src/lib/booking.ts`)。

- 並べ替えは純粋関数にして lib に置き、(カテゴリ順, メニュー順, id)の3段で並べる。
  取得側では `category_id` とカテゴリの `display_order` も取る
- 影響する画面: 予約カレンダーの予約ダイアログ、`/admin/reservations/new`、`/admin/reservations/[id]/edit`
- 店側でもカテゴリの見出しで区切るかは、モックDを確認して決める

## ② キャンセルボタンを破壊的アウトラインにする

モックは枠 `#e6c3bd`・文字 `#c0503f`・枠の太さ1.5px。対象は店側の予約詳細の
「店側でキャンセル」と、客側 `/my` の予約カードの「キャンセル」。現状はどちらも、
ニュートラルな枠に `text-destructive` を重ねている。

実装(2026-10-19。③と、見比べで見つかった「アウトラインの地の色」「キャンセルするの色」を
まとめて扱った):

- モックは `#c0503f` を、破壊的ボタン・必須マーク・休業バッジ・日曜の文字など、警告系の
  すべてに一貫して使っている。そこで、色を新しく足すのではなく、`--destructive` の値を
  `oklch(0.574 0.148 30.8)`(= `#c0503f`、白地で4.71:1)に変えた。キャンセル確認シートの
  「キャンセルする」もこれでモックの色になった
- 枠は `--color-destructive-soft` とした。`--destructive` と `--card` を oklab で35%混ぜた派生で、
  `#eec2ba`。oklch で混ぜると、`--card` の色相0が補間に入ってピンク寄りになるため、oklab にした
- `Button` に `outline-destructive` を足した(hover は地の濃さ3%。5%だと4.41:1でAAを割る)
- 既存の `outline` も、モックのニュートラル(地 `#fff`・枠 `#d5d2ca`・文字 `#5b6270`)に寄せた。
  地は `bg-card`、枠は `--input`(`#ded5d1`)、文字は `muted-foreground`(白地で5.54:1)
- アプリ内ブラウザで実測した: マイ予約、キャンセル確認シート、予約詳細、設定画面

## ③ 「マイ予約を見る」をテーマ色アウトラインにする

モックは枠がテーマ色、文字がテーマ色の濃い側。現状はニュートラルな枠に
`text-primary`(白地で4.38:1でAAに届かない)を重ねている。M4bの設定フォーム3つに
重複しているクラス文字列(border-primary / text-primary-strong)を `Button` のvariantに
まとめ、「マイ予約を見る」もそれを使う。

実装: `outline-accent` を足し、設定フォーム3つの定数と「マイ予約を見る」を置き換えた。
完了画面は予約を確定しないと出せないため、「マイ予約を見る」はブラウザで見ていない。

## ④ ボタンの太さ(と枠の太さ)

モックの `<button>` 28個はすべて `font-weight: 700` で、アウトラインの枠はすべて1.5px。
実装のベースは `font-medium` で、枠は1px。`<Button>` 44箇所のうち23箇所は、個別に
`font-bold` を付けている。

決定(2026-10-19、ユーザー): 共有のベースを `font-bold` と `border-[1.5px]` に変え、
ボタンごとに付けた `font-bold` は消す。あわせて、ボタンごとに500へ戻していた
`font-medium` 10箇所も消した。

実機で確認した範囲(2026-10-19): 店側(カレンダー日・週、予約詳細、代行登録、設定4画面、
カテゴリ編集ダイアログ)と、客側(予約フローの確認画面まで、マイ予約、キャンセル確認シート)。
どの `Button` も700で、1.5pxのクラスが付いている。

確認できていないもの:
- ログイン画面: 確認するにはログアウトが必要
- 予約完了画面(「マイ予約を見る」): 確認するには予約を確定する必要がある

### 見比べで見つかった差分

アウトラインの地の色と「キャンセルする」の色は、②でまとめて直した。

残っていた4つも、同じ日に直した(実機で数値を確認済み):

- **トグル類の太さ**: 生の `<button>` で作ったトグル・チップを、選択状態にかかわらず
  font-bold にした。対象は、営業日・スタッフ設定の曜日チップ、第Nチップ、スタッフ選択チップ、
  例外日と臨時休のセグメント切り替え、カレンダーの「今日」「日/週」、スマホの「タイムライン/リスト」。
  セグメント切り替え2つはモックに画面が無く、同じ種類なのでそろえた
- **予約詳細のボタンの高さ**: 下部のボタンを46pxにした(確認ステップの「キャンセルする/戻る」も)。
  メモ編集中の小さな「保存/キャンセル」はそのまま。モックの文字は15px、実装は14pxという差も残っている
- **破壊的ボタン**: `destructive` variant を、`#c0503f` の塗りに白文字(4.71:1)にした。
  hover は黒を10%混ぜて濃くする(5.96:1)。店側の確認の「キャンセルする」(旧4.12:1)と、
  客側のキャンセル確認シート(旧hover 3.99:1)の両方でこれを使う
- **「カテゴリを追加」**: `outline-accent` に、破線の枠と `bg-accent` を重ねた。文字は地の上で5.49:1。
  `--accent`(`#f6e3df`)は、モックの `#F3EBEA` より少し彩度が高い

まだ残っているもの:

- 「スタッフを追加」はニュートラルのまま(モックにこのボタンは無い)
- `.dark` 側の `--destructive` に白文字を置くと2.89:1。今は `.dark` を付ける処理が無く、
  到達できない(M4cの申し送りの範囲)

## ⑤ 予約カレンダーの時刻ラベル

- 週表示で「20:00」の左端が欠けていた。時刻の列の幅が、週表示は `w-12`、日表示は `w-14` だった
- 時刻ラベルの置き方が3通りに分かれていた。先頭は罫線の下、途中は罫線の中央、末尾は罫線の上
- モックは、時刻の列が62px幅で、どのラベルも上端を罫線にそろえて罫線の直下に置く

決定(2026-10-19、ユーザー): モックどおり、すべてのラベルを罫線の直下にそろえる。
当初は末尾(閉店時刻)のラベルを出さない予定だったが、同日のうちに「末尾も表示する」に
変わった。閉店時刻のラベルはモックには無く、ここはモックと違う。

- すべての目盛りに罫線を引き、ラベルも出す。末尾のラベルは時間軸の下へ1行分
  (mt-0.5 + text-xs ≒ 1.125rem)はみ出すので、時間軸の外側の下に余白を取る。
  日表示PCと週表示には `pb-5` を足し、スマホは既存の `pb-6` に収まる。
  本体の高さを変えないので、空き枠クリックの縦比率から時刻を出す計算はずれない
- 時刻の列の幅は、日表示・スマホ・週表示のどれも `w-16` にそろえる。数字は `tabular-nums` にする
