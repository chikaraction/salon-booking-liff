# UIの決まりごと

画面はモック(`docs/mockups/`)を正とする。ここには、モックに無い画面にも当てはめる
共通の決まりを置く。決まりを足したら、既存の画面もそれに揃える。

## ボタンの並び(2026-10-26)

ダイアログ・シート・確認ステップで「決定」と「やめる(キャンセル・戻る)」を並べるときの順番。
Apple HIG・Material Design 3 に合わせる。どちらも「横並びは決定が右、縦並びは決定が上」で、
モックF詳細(カテゴリ編集ダイアログ)とモック07(キャンセル確認シート)もこの並び。

| 置き方                               | 並び                                                                         | 例                                                       |
| ------------------------------------ | ---------------------------------------------------------------------------- | -------------------------------------------------------- |
| モーダル・確認ステップの**横並び**   | 右寄せ。**やめる(左) → 決定(右)**。横幅いっぱいに2分割するときも同じ順番     | カテゴリ編集、メニュー編集、予約詳細の店側キャンセル確認 |
| シート・確認の**縦並び**(スマホ向け) | **決定(上) → やめる(下)**                                                    | 客側のキャンセル確認シート、変更ダイアログの「詳細に戻る」 |
| ページ内の**インライン編集**         | 左寄せ。**決定(左) → やめる(右)**。決定ボタンは節の入力欄の直下に置く        | 設定画面の各節、スタッフの編集・追加、休業日の追加、スタッフメモ |

- 「やめる」は `outline`(インライン編集では `ghost` も可)、決定は塗り。破壊的な決定は `destructive`
- 「変更」「店側でキャンセル」のように、やめるボタンを含まない2つの操作の並びはこの表の対象外(モックに従う)
- 参考: Windows(Fluent)は逆で、決定が左・閉じるが右。このアプリでは採らない
- **破壊的な確認は、出てから0.5秒は決定を押せなくする**(2026-10-26)。ボタンを押すと
  同じ場所に確認ステップが出る作りでは、決定(右)が直前に押したボタンの位置に重なることがあり、
  素早い2回押しで確認を飛ばしてしまうため。予約詳細の店側キャンセル確認で、
  「店側でキャンセル」と「キャンセルする」が縦に14px重なっていた

出典:

- [Alerts | Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/alerts) — "Always place the default button on the trailing side of a row or at the top of a stack."
- [Dialogs – Material Design 3](https://m3.material.io/components/dialogs/guidelines) — 決定はダイアログの端寄り、やめるは決定の左。縦に積むときは決定が上
