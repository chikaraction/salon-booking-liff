## 管理画面でスタッフの写真を登録できるようにする(2026-11-16)

### 現状

- `staff.photo_url`(URL の文字列)の列はある(`supabase/migrations/20260716000000_initial_schema.sql`)
- 客側の予約画面の「スタッフを選ぶ」ステップは、`photo_url` があればその写真を丸く出し、
  無ければ名前の 1 文字目の丸を出す(`src/app/booking/_components/step-staff.tsx`。
  データは `src/server/booking-data.ts` の `getBookingPageData` で読む)
- **写真を登録する手段がない**: 管理画面のスタッフ設定に写真の欄が無く、開発用のダミーデータ
  (`supabase/seed.sql`)にも入っていない。そのため、いつも名前の 1 文字目の丸が出る。
  写真を出すには DB を直接書き換えるしかない
- モックの申し送り(`docs/mockups/README.md` の Assets)には「実装時はスタッフ写真をアップロード可能に」とある。
  M1 で列と表示だけ作り、登録の画面は作らなかった

### 選択肢

| 案                             | 内容                                                      | 良い点                             | 気になる点                                                                             |
| ------------------------------ | --------------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------- |
| A. 画像の URL を入れる欄を足す | スタッフ設定に URL の入力欄を足す                         | 小さな変更で済む                   | オーナーが画像をどこかに置いて URL を貼る必要があり、IT に詳しくないオーナーには難しい |
| B. 写真をアップロードできる    | スタッフ設定で写真を選んで送ると、Supabase Storage に置く | モックの申し送りどおり。扱いやすい | 規模が大きい。ADR を起こしてから進める(下の「B で決めること」)                         |
| C. 列と表示を消す              | `photo_url` の列と、写真を出す分岐を消す                  | 中途半端な状態がなくなる           | マイグレーションと表示の変更が要る。あとで写真を出したくなったら作り直し               |

いまは、店では運用せず参考実装として公開している状態なので、手を付けない(表示は名前の 1 文字目の丸で成り立っていて、モックも同じ見た目)。

### B で決めること

- **Storage を有効に戻す**: 手元の Supabase では、使わないサービスとして止める設定にした
  (`supabase/config.toml` の `[storage] enabled = false`。ブランチ `chore/local-supabase-slim`。
  開発用のバックアップの DB のフォルダも同じ)
- バケットを公開にするか(客側の画面からそのまま読めるか)、署名付き URL にするか
- 誰がアップロードできるか(Storage の RLS。スタッフ本人も自分の写真を変えられるか、オーナーだけか)
- 画像の大きさと形式の上限、スマホで撮った大きな写真の縮小をどこでするか
- 写真を差し替えたり、スタッフを消したりしたときに、古い画像を消すか
- Cloudflare Workers を経由して送るなら、その要求の大きさの上限(未確認)
- 客側の表示で next/image を使わない理由(外部 URL のドメインが店の運用で変わる)が、Storage にしても当てはまるか
