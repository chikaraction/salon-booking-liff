# 予約システム実機確認チェックリスト

ユニットテストとビルドが通っても、以下はデプロイ環境・LINE実機・複数端末で
のみ確認できる。tendledgeのverify-tauriスキルと同じ運用: **機能を追加したら
対応するチェック項目をここに追記する**。

## ダブルブッキング防止(ADR-004)

- [ ] 2つのブラウザで同じスタッフ・同じ時間帯の予約画面を開き、ほぼ同時に
      確定 → 片方だけ成功し、もう片方に「その枠は埋まりました」が表示される
- [ ] キャンセル済み予約と同じ枠に新規予約できる(WHERE status='confirmed' の確認)
- [ ] 所要時間の長いメニュー(例: 180分)が、途中の時間帯の別予約と重複できない
- [ ] スタッフの休憩・予約不可時間に重なる枠が客側に表示されない

## 客側予約フロー(M2)

- [ ] 日時選択で、埋まっている時刻が取り消し線+グレーで表示され押せない。
      勤務時間・所要時間の関係で確保できない時刻はそもそも表示されない
- [ ] 直前締切(開始60分前)を過ぎた当日の枠、受付期間(30日先)を超える日付が
      選択できない(いずれも salon_settings の値。変更したら反映されること)
- [ ] 「どちらでも」で予約 → 空いているスタッフのうち表示順が小さい方
      (実質オーナー)に割り当てられる。オーナーが埋まっている枠では
      もう一方に割り当てられる
- [ ] 初回予約で customers に1行だけ作成され、ご要望欄が reservations.note に、
      メニューのスナップショット(名前・料金・所要時間)が reservation_menus に入る
- [ ] メニュー選択でカテゴリ見出しに説明文(menu_categories.description)が表示される
- [ ] 完了画面に「確認のメッセージをLINEにお送りしました」が**表示されない**(M5まで)

## マイ予約・キャンセル・変更(M3)

- [ ] **変更の競合ロールバック**: 客Aが変更の確認画面まで進んだ状態で、別ブラウザの
      客Bが変更先と同じ枠を先に予約 → 客Aの変更確定は「その枠は埋まりました」になり、
      **客Aの元の予約が confirmed のまま無傷で残っている**(DBで status を確認)
- [ ] キャンセル直後に同じ枠が別客の日時選択に「空き」として出る
- [ ] 変更で「同じ枠のままメニューだけ追加」「同じスタッフで30分ずらし」ができる
      (自分の旧予約の枠が「埋まり」表示にならない)
- [ ] 締切(開始 cancel_deadline_minutes 前)を過ぎた予約は変更・キャンセルボタンが
      無効化され「お店に直接ご連絡ください」が表示される。salon_settings の値を
      変えると反映される
- [ ] Server Action を直接叩いて他人の予約IDのキャンセル・変更を試みる → 拒否され、
      対象予約に変化がない(RPC内の本人確認)
- [ ] LINE実機: リッチメニューの「マイ予約」ボタンから /my が直接開く(M6デプロイ後)

## LIFF・LINEログイン(ADR-003)

- [ ] LINEアプリのリッチメニューから予約画面が開き、ログイン操作なしで
      本人が特定されている(初回は名前・電話番号の入力画面が出る)
- [ ] 2回目以降の予約で個人情報の入力がスキップされる
- [ ] マイ予約に自分の予約だけが表示される(他人の予約が見えない)

## 通知(ADR-002)

- [ ] 予約確定時にLINEトークへ確認が届く
- [ ] 前日リマインドが指定時刻に届く(Cron Triggerの動作確認)
- [ ] 管理画面のプッシュ送信数カウンタが送信のたびに増える

## 管理画面(ADR-005)

- [ ] 未ログイン状態で /admin 配下のURLを直接開くとログイン画面に飛ばされる
- [ ] スタッフ権限でオーナー専用機能(スタッフ管理・メニュー管理)が操作できない
- [ ] 代行登録した電話予約が客側の空き枠計算に即時反映される

## レスポンシブ(ADR-005)

- [ ] 管理画面をスマホ幅で開く → カレンダーが1スタッフ切替またはリスト表示に
      切り替わり、横スクロールが発生しない
- [ ] 客側の全画面がスマホ縦(LINE内ブラウザ)で崩れない

## データ設定(ADR-007)

- [ ] メニュー・カテゴリ・営業時間を管理画面から変更 → コード変更なしで
      客側の表示・空き枠計算に反映される
